# Phase 2 구현 및 검증 기록

검증일: 2026-10-30 · 환경: macOS, Node.js 24.15.0

## 구현 범위

| 영역 | 구현 내용 |
| --- | --- |
| 원료 | 코드 중복 차단, 등록·조회·수정, 미참조 원료 삭제, 사용 중지, 별칭 검색, CSV 내보내기 |
| 제조 LOT | 원료별 제조번호 등록·수정·검색, 선행 0 유지, 원료와 제조번호 조합의 중복 차단 |
| 입고건 기초정보 | 같은 제조 LOT의 분할 입고 구분, 시험번호·품질 판정·기한·사유 관리, 품질 변경 이력 |
| 창고·위치 | 등록·수정·사용 중지, 창고별 위치 목록 |
| 재고 | 원료 합계 및 LOT·입고건·위치별 상세, 현재고·예약·가용·사용불가 수량, 필터·페이지네이션·CSV |
| 권한 | 활성 Viewer/Operator/Admin 조회, Admin 기준정보 변경, 모든 앱 역할의 재고 직접 변경 차단 |
| 가상 데이터 | 원료 6개, LOT 6개, 입고건 8개, 창고 3개, 위치 5개, 위치별 잔량 10개 |

참고 엑셀에서 확인한 **원료 별칭**, **제조 LOT와 입고·시험번호의 구분**, **기본단위·포장규격·밀도의 분리**를 반영했다. 실제 회사 데이터와 원본 엑셀은 저장소나 외부 서비스에 업로드하지 않았다.

입고건 등록은 기초정보만 생성하고 수량을 늘리지 않는다. 입고·불출·반납과 거래 감사추적은 Phase 3에서 구현한다. Excel/XLSM 및 CSV 업로드, 대시보드 통계와 AI 분석은 이번 구현 범위에 포함하지 않는다.

## 자동 검증

| 명령 | 결과 |
| --- | --- |
| `node node_modules/vitest/vitest.mjs run` | 5개 파일, 169개 테스트 통과 |
| `node node_modules/nuxt/bin/nuxt.mjs typecheck` | 통과 |
| `node node_modules/nuxt/bin/nuxt.mjs build` | Nuxt 프로덕션 빌드 통과 |
| `node --test tests/integration/*.test.mjs` | 14개 HTTP 통합 테스트 통과 |
| `git diff --check` | 공백 오류 없음 |

위 명령은 `pnpm test`, `pnpm typecheck`, `pnpm build`, `pnpm test:integration`에 대응하는 설치된 로컬 실행 파일을 직접 호출한 것이다.

주요 검증 항목:

- 실제 SQL migration과 seed를 PGlite PostgreSQL에서 실행하고 역할별 RLS와 권한을 확인했다.
- 음수·과도한 소수점·NaN·예약 초과, 원료코드·LOT·입고번호 중복을 차단한다.
- 등록된 LOT의 소속 원료, 입고건의 LOT, 위치의 창고를 임의로 바꿀 수 없다. LOT가 있는 원료의 기본단위도 고정한다.
- 제조일·입고일·판정일·기한의 순서를 검증하고 미래 입고일·판정일은 한국 시간 기준으로 거부한다.
- 기한 경과는 원래 QC 판정을 보존하면서 계산한다. 유효기간 미확인, 비적합 품질상태, 사용 중지 원료·창고·위치는 가용량 0으로 처리한다.
- 원료 합계와 위치별 잔량이 일치하며, 재고가 없는 원료도 합계 목록에 나타난다. 각 원료의 단위는 별도로 유지한다.
- 품질 변경 시 처리자·시점·사유·판정과 시험정보를 누적 보존하고 앱에서 이력을 수정할 수 없도록 한다.
- 세션 갱신 후 같은 요청의 재고 조회에 갱신된 인증을 사용하고 쿠키를 응답에 반영한다.
- 인증 없는 조회, Viewer/Operator의 변경 요청, 다른 Origin의 변경 요청을 차단한다.
- CSV는 검색 조건을 적용하고 수식 주입 문자를 처리한다. 1,000건 단위로 조회하며 10,000건 초과 시 명시적으로 거부한다.

HTTP 통합 검증은 빌드된 Nuxt 앱과 실제 Supabase JS/SSR 클라이언트를 사용했다. Auth 및 PostgREST 전송 계층은 로컬 모형이며, 업무 데이터와 권한 검증은 실제 migration을 적용한 PGlite에서 처리했다. 실제 Supabase Cloud 연결 검증을 대신하지 않는다.

## 브라우저 검증

가상 계정과 로컬 모형을 연결한 프로덕션 빌드에서 다음을 확인했다.

- 관리자 로그인 후 원료·재고·창고 화면 이동
- 원료 등록, 별칭 검색, 검색 결과 새로고침 유지
- 선행 0이 있는 LOT 등록과 원료 상세 표시
- 품질상태 `기한 경과` 필터의 결과 및 새로고침 유지
- 원료별 합계 전환과 재고 없는 원료의 표시
- 사용 중지 위치·창고의 가용량 0 및 사유 표시
- LOT 선택과 연결 입고건·QC 이력 모달, 선택한 LOT의 새로고침 복원
- 선택한 창고를 포함한 URL 직접 접근 및 연결 위치 표시
- 1024×768 크기에서 본문 가로 넘침 없이 표 내부 가로 스크롤 제공
- 최종 브라우저 콘솔의 경고·오류 없음

## 적용 상태와 후속 작업

**실제 Supabase 프로젝트에는 이번 migration과 seed를 적용하지 않았다.** 기존 테스트 프로젝트에 Phase 1이 적용되어 있다면 아래 순서로 추가한다.

1. `supabase/migrations/20261030000100_inventory_foundation.sql` 적용
2. 가상 데이터 전용 프로젝트에서 `supabase/seed.sql` 실행
3. 실제 Supabase Auth 계정으로 Viewer/Operator/Admin 권한과 위 화면 시나리오 확인

seed는 사용자 계정·비밀번호를 만들지 않으며, 재실행 시 기존 업무 데이터와 수량을 덮어쓰지 않는다. 실행 방법은 [README](../README.md), 재고 계산과 권한 정책은 [DATABASE](./DATABASE.md)를 참고한다.
